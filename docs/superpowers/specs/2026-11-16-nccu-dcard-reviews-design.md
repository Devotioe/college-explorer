# 全政大 Dcard 心得清理、擴充與網站整合設計

## 目的

將同學放入 `data/dcard` 的候選文章、課程心得與教師心得整理成可追溯、可核對的正式資料，接到 Course Compass 的政大課程詳情；再沿用「政大課表／教師名錄作為種子，透過公開搜尋尋找 Dcard 政大板文章」的方法，將搜尋範圍擴至全政大。

## 目前基線

- 候選資料 889 列、646 個不重複貼文 ID，其中 243 列是重複貼文。
- 498 列是標準 `dcard.tw/f/nccu/p/<id>` 政大板文章網址；其餘 391 列包含其他看板、留言網址或非標準網址。
- SQLite 中有 37 筆來源、33 篇不重複貼文；現有正式摘要為 72 筆課程心得與 30 筆教師心得。
- 現有心得只涵蓋資訊科學系與資訊管理學系，但 72 筆課程心得的課名都能在同學的歷年課表中找到。
- 公開搜尋已證明能找到政經、商學、傳播、外文、通識與體育等其他領域文章。

## 使用者選定方案

採用「分層混合模式」：正式心得、待核對資料與排除資料分流處理。沒有通過正式規則的資料不得出現在一般使用者的課程頁。

## 資料分層

### 正式心得（published）

必須同時符合：

1. 來源是標準政大板文章網址，且貼文 ID 可解析。
2. 能取得可供核對的公開文章內容或足夠的公開搜尋內容；只有標題或網址不算。
3. 課名能以正規化後的完整名稱配對政大課程庫。
4. 教師若出現在內容中，必須能配對該課的歷年授課教師；教師缺漏時，需有學期或系所等另一項佐證。
5. 摘要只保留課程內容、評量、作業、出席、負擔及學習經驗，不保留作者身分或無關個人資訊。
6. 同一 `post_id + course_id + teacher + semester` 只保留一筆；完整來源優先於搜尋摘要。

### 待核對（quarantine）

包含只有搜尋摘要、課名有多個可能配對、教師與歷年課表不一致、學期不明或內容不足的資料。保存在資料檔與內部狀態中，但不提供一般前端 API。

### 排除（rejected）

包含非政大板、留言分頁網址、完全重複、來源撤下、無課程內容、問課但沒有心得、無法配對政大課程，以及明顯不相關文章。

## 資料模型

新增 D1 表 `student_course_reviews`：

- `id`
- `course_id`，關聯現有 `courses.id`
- `school`，本階段固定 `NCCU`
- `teacher`
- `semester`
- `summary`
- `source_url`
- `source_post_id`
- `source_kind`（全文核對／公開搜尋摘要）
- `verification_status`（published／quarantine／rejected）
- `created_at`、`updated_at`

正式資料以 `course_id + source_post_id + teacher + semester` 建立唯一性保障。原始文章全文不匯入網站 D1，只保存整理後摘要與來源連結。

## 清理與匯入流程

建立可重跑的處理腳本：

1. 從 `collector.sqlite3` 與 CSV 讀入候選、來源、課程心得及教師心得。
2. 正規化 Dcard URL，留言網址折回主文；依貼文 ID 去重。
3. 以 `data/course-seed.json` 的 NCCU 課號、課名、系所與教師進行配對。
4. 按上述規則分成 published、quarantine、rejected。
5. 輸出可檢查的 JSON 與品質報告，列出各層數量、排除原因、重複率及無法配對項目。
6. D1 bootstrap 只匯入 published；quarantine 保留在 repository 供日後人工補資料。

## 全政大公開資料擴充

以政大課程庫與教師名錄生成查詢，不限定資科、資管：

- `site:dcard.tw/f/nccu/p/ "課程名稱"`
- `site:dcard.tw/f/nccu/p/ "教師姓名" "課程名稱"`
- `site:dcard.tw/f/nccu/p/ "修課心得"`、`"選課心得"`、`"課程心得"`，依年度切分。

蒐集僅使用公開搜尋結果與可公開開啟的文章頁，保存短摘要與原文連結，不大量重製文章全文。第一輪涵蓋所有政大系所的查詢種子，優先處理近年、可匹配多門課的綜合心得文章；沒有結果的課程保持「尚無學生心得」，不製造內容。

## 網站介面

政大課程詳情新增「學生公開心得」區塊：

- 顯示正式心得數量。
- 每張卡顯示學期、教師、摘要與「查看 Dcard 原文」。
- 固定顯示「心得為學生主觀經驗，課程安排可能隨學期與教師調整」。
- 沒有正式心得時顯示簡潔空狀態，不顯示待核對內容。
- 本階段不新增側欄、不新增獨立心得搜尋頁。

## 推薦系統邊界

第一階段不把甜度、涼度、成績或情緒直接加入推薦分數。心得文字只用於課程詳情與可解釋資訊；等全校覆蓋率與每門課樣本量足夠後，再另行設計推薦訊號，避免少數主觀心得造成偏差。

## 方案比較

- 嚴格模式：可信但覆蓋低。
- 全自動模式：覆蓋高但誤配與無關內容風險大。
- 分層混合模式：正式資料維持嚴格，疑似資料保留待核對；使用者已選擇此方案。

## 非目標

- 不繞過登入、付費牆、robots 或網站安全限制。
- 不保存或公開作者帳號、個人資料與完整文章副本。
- 不保證每一門政大課程都能找到 Dcard 心得。
- 不在本階段用主觀心得改變推薦分數。

## 驗收標準

1. 現有候選可重現地分成 published、quarantine、rejected，且每筆都有原因或來源。
2. 正式心得沒有重複主鍵、沒有非政大板網址、沒有無法配對的課程。
3. 課程詳情 API 只回傳 published。
4. 有心得的政大課程能在前端看到摘要及原文連結；無心得課程顯示空狀態。
5. 全政大查詢種子涵蓋所有 NCCU 課程系所，不再限定資科與資管。
6. TypeScript、資料品質測試、ESLint 與正式建置通過。
